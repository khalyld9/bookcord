System overview • Bookcord Library Hub

Every tap, mapped.
Student & Admin journeys.

Bookcord is a school library system for checking textbook stock and reserving titles. Students browse an ICT-filtered catalog, save titles, reserve with a QR claim code, and track syllabi. Admins run the desk: inventory, reservations, claim scanning, checkouts, and the Booky chat inbox. Both roles share the same Next.js + Supabase core with role-based guards.

🔐 Guard everywhere

middleware.ts → updateSession refreshes Supabase session on every request. Then:

  • requireUser() → redirect /login
  • requireAdmin() → role ADMIN && status ACTIVE else → /books
  • Every server action re-checks admin (restock, adjust, addBook, claim…)

📦 Stock is single-source

  • restock_book +N → inventory ↑ + restocks + stock_movements RESTOCK
  • issue_book −N on claim → book_issues ISSUED + issued_stock ↑
  • return_book +N → book_returns + stock back
  • adjust_inventory ±N → audit reason DAMAGED/CORRECTION

💬 Realtime chat

  • Student Booky → chat_messages STUDENT
  • Admin reply → sender ADMIN
  • Admin inbox groups by profile_id, live via Supabase Realtime
  • FAQ shortcut: upcoming_restocks shows next titles
💡
How a QR claim actually works — 6 steps

Student reserves in catalog → gets QR + 8-hex code (PENDING) → admin marks READY (bell) → student shows QR at desk → admin scans at /admin/claim (jsqr or typed) → claimReservation validates PENDING/READY + stock, then issue_book RPC creates the checkout and flips reservation to CLAIMED. If shelf is 0, error instructs to restock first.
